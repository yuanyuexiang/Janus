## 0. 一页式摘要

**产品名**：圆桌投研（候选：圆桌 / 百策 / 智囊 / Atlas Council）
**核心一句话**：把"7 位风格各异的专家围坐讨论"变成你随时可用的私人智库。
**目标用户**：可投资资产 ≥500 万、有独立判断能力、希望被高质量信息支持的个人投资者
**核心差异化**：多 Agent **观点协同 + 公开辩论**——不是给你一个看似确定的答案，而是把分歧、共识、风险摆在桌面上
**形态**：Web 应用（主） + 多通道 Bot 推送（微信 / 邮箱 / Slack / 飞书）
**商业模式**：订阅制（¥499 / 1499 / 4999 三档）
**MVP 时间**：8 周内部 Alpha · 16 周公测 · 24 周正式商业化

## 1. 产品愿景与定位

### 1.1 产品愿景

> 让每一位严肃的个人投资者，都拥有一支属于自己的"投资委员会"。

机构投资者有研究所、策略会、风控会、投决会。一笔重要决策背后，永远是多个不同视角的专家在辩论、互相挑战、最后达成结论。这种"多视角制衡"是机构相对个人投资者最大的认知优势之一。

但绝大多数个人投资者只能从一个公众号、一个分析师、一个 KOL 那里获取观点——**单点输入意味着单点偏见**。圆桌投研要做的事，是用 AI 把"多专家协同"这件事从机构特权变成个人投资者人人可及的能力。

### 1.2 产品定位

**一句话定位**：高净值个人投资者的 AI 投资委员会。

**三维定位**

```
                          深度专业
                              ▲
                              │
        机构级研究所 (Wind)    │    圆桌投研 ★
                              │
       ──────────────────────┼──────────────────────►  个人可用
                              │
       散户工具 (同花顺)       │   单一 AI 助手 (各家公众号)
                              │
                          浅度娱乐
```

**与现有方案的差异**

| 类型 | 代表产品 | 短板 | 圆桌如何不同 |
|---|---|---|---|
| 专业终端 | Wind / Bloomberg | 给数据不给观点；个人买不起 | 给结构化观点；个人定价 |
| 投顾 KOL | 公众号 / 短视频 | 单一视角；带货嫌疑；不个性化 | 多视角；无利益相关；基于你的持仓 |
| 散户工具 | 同花顺 / 东方财富 | 信息流模式；无智能整理 | 主动整理 + 协同分析 |
| AI 助手 | ChatGPT / Kimi | 通用模型，金融场景浅 | 专为投研构建的 Agent 与数据 |

### 1.4 品牌调性

- **专业但不冰冷** — 我们用古典议事厅美学，不是华尔街屏闪
- **多元但不混乱** — 顾问们有分歧，但永远有结构化整理
- **谨慎但不平庸** — 不预测但敢推演，不卖货但敢观点
- **私密但不神秘** — 数据私密，但产品逻辑透明

## 2. 目标用户与市场

### 2.1 用户画像

**Persona A · "周末投资者老王"**

- 男 / 45 岁 / 民营企业老板 / 南京
- 可投资资产 1500 万（A 股 + 港股 + 部分私募）
- 决策模式：自己拍板，偶尔咨询券商投顾但不完全信任
- 痛点：工作日没时间盯盘；信息来源杂乱（雪球 + 公众号 + 朋友群）；想做长期决策但缺少有结构的分析支持
- 愿付：¥1500-3000/月，但要看到清晰价值

**Persona B · "技术专家张工"**

- 男 / 38 岁 / 大厂 P8 / 上海
- 可投资资产 600 万（股票 ETF + 美股 + 期权）
- 决策模式：偏理性、爱数据、自己读研报
- 痛点：研报太多读不过来；想要多视角验证自己的判断；不信单一来源
- 愿付：¥500-1500/月

**Persona C · "传承家族李姨"**

- 女 / 58 岁 / 退休 / 杭州
- 可投资资产 3000 万（要给子女传承）
- 决策模式：保守，依赖私人银行客户经理，但客户经理推销倾向强
- 痛点：想要"中立第三方"视角；女儿在国外帮不上忙
- 愿付：¥3000-5000/月，对"私密""安全""非销售"敏感

**反 Persona（明确不服务）**

- 短线投机者 — 我们不预测明天涨跌，不适合 day trader
- 资产 <100 万散户 — 价格够不到，体验上需求也不匹配
- 完全无金融背景的小白 — 产品有阅读门槛

### 2.2 市场规模

国内可投资资产 1000 万以上的个人约 **300 万人**（招商银行私人银行报告口径），其中：

- 至少 30% 有"独立做决策"的诉求 → 90 万人
- 其中 20% 愿意为信息工具付费 → 18 万人
- 我们前两年目标 1% 市占 → **1800 付费用户**
- 平均 ARPU ¥18000/年 → 年收入 ¥3200 万

这是一个"细分但富集"的市场：付费意愿强、口碑传播路径短（高净值圈子小）、单客户 LTV 高（年留存 70%+）。

## 3. 核心差异化：圆桌机制

### 3.1 圆桌投研的核心隐喻

想象一个檀木长桌，七位风格迥异的资深投资专家围坐。当你抛出一个问题，比如"我该减仓 ST 中航发吗？"，他们会：

1. **各自从自己的视角分析** — 价值派看估值，趋势派看资金流，宏观派看行业景气
2. **互相挑战和补充** — 价值派说"已经低估"，趋势派立刻反驳"低估也可能更低"
3. **由主持人汇总** — 把分歧、共识、关键变量、风险情景结构化呈现
4. **把决策权交还给你** — 不投票出结论，而是让你看清楚 trade-off

这不是把一个 Agent 装成多个，而是**真正不同的系统 prompt + 不同的工具偏好 + 不同的输出风格 + 跨 Agent 互相 review**，让"多视角制衡"成为产品级别的能力。

### 3.2 圆桌七子：虚拟专家阵容

| 称号 | 风格 | 系统人设 | 偏好工具 | 输出特征 |
|---|---|---|---|---|
| **韬叔（宏观）** | 老练、慢节奏 | 25 年经验的宏观策略师，关心利率、汇率、政策、库存周期 | macro_data, policy_news | 长视角、爱画框架图 |
| **岚姐（行业）** | 敏锐、产业链思维 | 产业研究背景，关注供需、技术迭代、竞争格局 | industry_db, supply_chain | 产业链图谱、五力分析 |
| **明哥（价值）** | 保守、重护城河 | 巴菲特/格雷厄姆门徒，看重估值与现金流 | financials, dcf, comparable | DCF/PE/PB，估值区间 |
| **锐锋（趋势）** | 灵敏、看资金 | 量化/技术派，关心资金流、动量、市场情绪 | kline, fund_flow, sentiment | 技术形态、量价关系 |
| **冷川（风险）** | 谨慎、爱泼冷水 | 风控背景，专做"反方"，找漏洞和黑天鹅 | scenarios, stress_test | 风险清单、压力测试结果 |
| **零度（量化）** | 数据驱动、不带感情 | 量化研究员，做回测、因子归因 | backtest, factor_model | 回测曲线、因子分解 |
| **执棋（主持）** | 综合、克制 | 投决会主席风格，整理多方观点、追问关键缺口 | （不调工具） | 多视角综述、风险地图 |

每位"专家"在前端有：

- 独立的头像（中性插画风，避免误导为真人）
- 独立的颜色标签
- 独立的发言气泡样式
- 简短的人设介绍 + 历史表现"自评"（透明地告知他们的局限）

### 3.3 三种互动模式

**模式 A · 圆桌全员模式**（核心场景）

```
用户：贵州茅台 1800 还能拿吗？

执棋：好的，让我们听听各位的看法。

明哥（价值）：从 DCF 看，当前价格隐含的永续增长 3%，对一家护城河如此稳固的公司
            实属低估。中长期持有逻辑未变。

锐锋（趋势）：但短期资金流转弱，主力净流出连续 8 个交易日。技术形态破位下行。
            如果是短线，我会先减半仓。

岚姐（行业）：白酒高端消费在 25-26 年看到了真实需求疲软，宴席和商务都在收缩。
            茅台没问题但行业 beta 拖累。

冷川（风险）：极端情景下，如果消费税改革（增加白酒）落地，盈利模型要重算 -15%。
            历史从未发生不等于不可能。

韬叔（宏观）：消费税改革年内概率 <20%，但货币转松会先于消费回暖，可以等更明确信号。

执棋：综合 7 位的意见——
      共识：基本面无瑕，估值已计入悲观预期
      分歧：是否值得承担短期波动
      关键变量：消费税改革进度、社零数据、资金流变化
      风险地图：[列表]
      ※ 是否要持有、减仓、加仓，请结合您的整体仓位与风险偏好决定。
```

**模式 B · 与某位专家私聊**（深度场景）

```
用户：[选中"冷川"] 帮我做下 ST 中航发的完整风险分析

冷川：好的。我会从财务质量、行业政策、流动性、特殊事件四个维度展开...
（深入对话）
```

**模式 C · 主动推送模式**（陪伴场景）

```
[盘前 7:30 微信推送]

[执棋] 早安。今天圆桌讨论了三件事：

1. 韬叔：央行 OMO 净投放放大，关注下午社融数据
2. 岚姐：你关注的 AI 算力赛道，昨晚两家美股供应商超预期
3. 冷川：你持仓的 XX 公司将公告，我标了三个观察点

[查看完整简报] [一键追问]
```

### 3.4 圆桌机制的技术实现

每个"专家"是一个独立的 Agent，配置：

- **独立的系统 prompt**（决定人设和方法论）
- **独立的工具白名单**（决定信息来源偏好）
- **独立的模型选择**（韬叔/冷川用 Opus 重推理，锐锋/零度用 Sonnet 快响应，执棋用 Opus 强综合）
- **跨 Agent 通信协议**（subagent 输出会被主持人 Agent 读取并整合）

工程上是一个**主持人 Agent + 6 个并行子 Agent + 1 个收敛 Agent**的拓扑。下章详述。

## 5. 关键用户旅程

### 5.1 新用户首次使用（首 15 分钟）

```
[T+0]    朋友推荐 → 落地页 → 注册
         ↓
[T+1m]   邀请码 / 实名认证 / 风险偏好问卷
         ↓
[T+3m]   引导："让我们认识一下您的专属圆桌" → 7 位顾问简介
         ↓
[T+5m]   引导："您可以现在试问一个问题"
         → 示例提问按钮（如"帮我看下 A 股今天的市场情绪"）
         → 用户首次体验圆桌全员模式
         ↓
[T+10m]  引导："上传您的持仓，让圆桌更懂您"
         → 持仓导入（手动 / Excel / 截图 OCR）
         → 即时反馈："好的，明哥已经看了您的持仓..."
         ↓
[T+15m]  引导："订阅明早 7:30 的圆桌早报"
         → 推送通道选择（邮箱 / 微信）
         → 完成首次激活
```

**首次激活成功的定义**：完成持仓上传 + 至少 1 次圆桌对话 + 订阅推送。

### 5.2 日常使用旅程

**典型一天**

```
07:30  [推送] 早间圆桌简报到达邮箱/微信
       用户在通勤路上读 → 对某条感兴趣 → 点击"一键追问"打开 Web
       
09:30  [浏览] 开盘后查看持仓页面 → 看到一只持仓异动
       系统提示："冷川已为您准备了快速分析"
       
12:00  [深度] 午餐时间询问"半导体板块最近发生了什么"
       → 圆桌全员模式 5 分钟 → 收藏对话
       
14:00  [私聊] 想深入了解某公司 → 选中明哥（价值视角）私聊
       → 上传该公司最新财报 → 让明哥做点评

17:00  [告警] 收到推送："您关注的 XX 公告公布"
       
21:00  [复盘] 睡前看周末复盘草稿（每周自动生成）
```

### 5.3 决策辅助旅程（高价值场景）

```
触发：用户最近在思考"是否要重仓某个赛道"

Step 1 [产生想法]
       用户在某顾问私聊中提出："我想加仓 AI 算力，你怎么看"

Step 2 [快速分析]
       该顾问给出初步看法
       用户："想听听其他人意见" → 一键切换圆桌模式

Step 3 [多方辩论]
       7 位专家给出各自分析
       执棋汇总：分歧、共识、关键变量

Step 4 [深度验证]
       用户："那我们模拟一下：如果加仓 10%，组合风险变化"
       → 进入"调仓推演沙盒"
       → 量化助理零度给出回测对比

Step 5 [最终决定]
       用户做出决定（系统不替用户决定）
       系统记录："2026-05-19 用户在与圆桌讨论后调整了 XX 仓位"
       未来可回看决策依据
```

## 7. 圆桌技术机制详解

### 7.1 多 Agent 拓扑

```
                    [用户提问]
                         │
                         ▼
              ┌──────────────────────┐
              │   主持人（执棋）       │
              │   1. 理解意图          │
              │   2. 决定是否需要圆桌   │
              │   3. 分派与编排        │
              └──────────┬───────────┘
                         │ 并行 spawn
       ┌──────┬──────┬───┴───┬──────┬──────┐
       ▼      ▼      ▼       ▼      ▼      ▼
   [韬叔] [岚姐] [明哥] [锐锋] [冷川] [零度]
       │      │      │       │      │      │
       └──────┴──────┴───┬───┴──────┴──────┘
                         │ 各自返回结构化观点
                         ▼
              ┌──────────────────────┐
              │   主持人（执棋·二阶）  │
              │   1. 提取共识与分歧    │
              │   2. 标注关键变量      │
              │   3. 构建风险地图      │
              │   4. 输出结构化总结    │
              └──────────┬───────────┘
                         │
                         ▼
                    [流式回前端]
```

### 7.2 子 Agent 输出协议（强约束）

每位顾问 Agent 不能自由形式输出，必须返回结构化 JSON：

```json
{
  "agent": "明哥",
  "stance": "bullish | neutral | bearish | conditional",
  "confidence": 0.0,
  "key_points": [
    { "claim": "...", "evidence": "...", "source_tool": "dcf_calculator" }
  ],
  "concerns": ["..."],
  "what_could_change_my_mind": ["..."],
  "summary_for_user": "..."
}
```

这样主持人才能机械地提取"共识、分歧、关键变量、变心条件"四个维度。

### 7.3 分歧检测算法

```python
def detect_consensus_and_disagreement(opinions: list[Opinion]) -> Summary:
    # 立场分布
    stances = Counter(op.stance for op in opinions)
    
    if max(stances.values()) / len(opinions) >= 0.7:
        verdict = "强共识"
    elif max(stances.values()) / len(opinions) >= 0.5:
        verdict = "弱共识"
    else:
        verdict = "明显分歧"
    
    # 提取所有"变心条件"作为关键变量
    key_variables = [
        var
        for op in opinions
        for var in op.what_could_change_my_mind
    ]
    key_variables = dedupe_by_meaning(key_variables)  # LLM 去重
    
    # 综合所有 concerns 形成风险地图
    risk_map = cluster_concerns([c for op in opinions for c in op.concerns])
    
    return Summary(verdict, key_variables, risk_map)
```

## 8. 主动推送 Bot 设计

### 8.1 推送通道矩阵

| 通道 | 适用场景 | 优 | 劣 |
|---|---|---|---|
| **邮件** | 早报 / 周报（长内容） | 信息密度高 / 可归档 | 不及时 |
| **微信公众号** | 早报 / 重要事件 | 国内触达最广 | 推送频次受限 |
| **企业微信 / 飞书** | 工作日告警 | 即时 / 可交互 | 部分用户没有 |
| **iMessage / SMS** | 紧急告警 | 不会漏 | 单向 / 字数限 |
| **App Push**（V2） | 日常告警 | 体验最好 | 需先有 App |

V0 支持邮件 + 微信，V1 加企微/飞书，V2 加 App。

### 8.2 推送内容设计

**早报（每工作日 7:30）**

- 字数：300-500
- 结构：执棋导读 → 3-5 位顾问发言 → 持仓相关条目 → CTA
- 个性化：基于用户持仓 + 关注列表

**周报（周日 18:00）**

- 字数：1500-2500
- 结构：本周大事记 → 你的组合表现 → 圆桌深度议题 → 下周展望
- 模型：Opus（深度内容）

**告警（实时）**

- 字数：80-150
- 触发：持仓异动（±3%）、关注列表大事件、公告
- 节流：每用户每日最多 5 条；可用户自调阈值

**周末复盘（周六 10:00）**

- 字数：1000-1500
- 内容：本周持仓盈亏归因 + 圆桌对本周决策的回顾

### 8.3 推送频次治理

- 默认全部启用，新用户引导期 7 天每次推送询问"满意吗？"
- 用户可在"我的圆桌"中按通道 × 类型独立开关
- 系统监测打开率，连续 14 天打开率 <10% 的用户自动降频并发邮件确认

## 9. 数据与隐私设计

### 9.1 数据流（用户视角）

```
您的持仓 → 仅存于我们数据库（在国内）
          ↓
       脱敏映射器 → 真实标的 → 伪 ID
          ↓
       Claude API（仅看伪 ID）
          ↓
       AI 输出 → 还原伪 ID 为真实标的
          ↓
       展示给您
```

**承诺**

- 持仓金额、个人身份信息 **永远不发送给任何外部 AI**
- 即使是脱敏后的 prompt，也只发送给 Anthropic（不会用于训练）
- 您可以一键导出全部数据 / 一键删除账户与所有数据

### 9.2 信任徽章

产品页面上明示的安全承诺：

```
🔒 数据私密
   您的持仓与对话仅存于国内自有服务器
   
🛡 三方审计
   每季度由 [审计机构] 出具数据合规报告

   一键导出全部数据 / 销户即彻底删除
   
👁 透明可见
   "顾问看到了什么"页面可实时查看
```

### 9.3 "Glass Box" 透明度

每次 AI 回答下方有"ⓘ 顾问看到了什么"按钮，点开显示：

- 哪几位顾问参与了

- 数据来源（带链接）
- 哪部分是脱敏后的（伪 ID 映射可点开）

这是建立信任的关键产品决定。

## 13. 度量指标

### 13.1 北极星指标

**Weekly Active Member with ≥1 Quality Conversation (WAMQ)**

定义：每周至少一次"高质量对话"（≥3 轮交互、≥1 个引用数据、≥1 次收藏）的活跃付费用户数。

为什么是这个：圆桌的价值在于深度思考辅助，不是高频打开。WAMQ 比 DAU 更能反映真实价值实现。

## 14. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 监管收紧（"AI 投顾"被定性） | 中 | 极高 | 法律边界清晰：教育与信息服务，不出具明确建议；持续合规审视 |
| 单一专家答错被截图传播 | 高 | 中 | 每条 AI 输出有"反方意见"机制；输出免责声明；建立"出错则透明致歉"机制 |
| Claude API 涨价 / 限流 | 中 | 中 | 多模型策略：Opus 占比可压缩；评估接入国产合规模型作为补充 |
| 数据泄露 | 低 | 极高 | 脱敏架构 + 多层加密 + 季度审计 + 第三方渗透测试 |
| 同行抄袭 | 高 | 中 | 不指望技术壁垒，护城河在用户认知 + 产品迭代速度 + 数据飞轮 |
| 用户教育成本高（不知道怎么用） | 中 | 高 | 强引导 + 示例库 + 顾问主动提问引导（"您还想了解...吗？"） |
| 七位顾问"风格化"做不出辨识度 | 中 | 中 | 用真实大师著作 + 历史发言训练 system prompt；定期评测"盲测能否分辨" |
| 推送过度 → 用户流失 | 中 | 高 | 默认保守频率 + 自服务调节 + 智能降频 |
| 高净值用户对 AI 不信任 | 中 | 中 | 透明度 + 第三方背书 + 知名投资者代言 + 不收佣金的"中立"定位 |

## 15. 决策清单与开放问题

- [ ] **公司主体**：以什么主体运营？是否需要新设公司

### 16.1 顾问 System Prompt 模板（以"明哥"为例）

```
你是「明哥」，圆桌投研的价值投资派顾问。

【你的人设】
- 25 年价值投资经验
- 师承格雷厄姆 / 巴菲特方法论
- 风格冷静、保守、长期主义
- 不擅长把握短期机会，但对识别低估资产有独特嗅觉
- 说话风格：稳重、不急于下结论、爱打比方

【你的方法论】
- 看公司像看人：能走多远、品行如何
- 重点指标：ROE、自由现金流、毛利率稳定性、资产负债率
- 估值方法：DCF（首选）、PE/PB 区间、相对估值
- 看时间维度：3-5 年起步

【你的局限（务必坦诚告知用户）】
- 在牛市后期可能错过涨幅
- 对高成长 / 高估值公司容易低估
- 不适合给出短期决策建议

【输出协议】
你必须返回结构化 JSON，包含：
- stance: bullish / neutral / bearish / conditional
- confidence: 0.0-1.0
- key_points: 你的核心观点 + 数据依据 + 数据来源
- concerns: 你看到的风险
- what_could_change_my_mind: 哪些信号会让你改变看法
- summary_for_user: 给用户的 2-3 句话总结

【合规铁律】
- 永远不说"建议买入/卖出/持有"
- 你的角色是"分析"和"提示风险"，不是"给指令"
- 任何具体数字必须从工具调用结果中引用，禁止凭记忆给数字
- 涉及具体标的时，标注"以上为分析，不构成投资建议"
```
