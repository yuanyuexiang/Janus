> MCP First 版本 · MVP 可执行方案  
> 版本 v2.0 · 2026-05-26

## 0. 版本说明

本版是在 v1.0 技术方案基础上的收敛版，目标是把方案从“完整平台蓝图”调整为“可以马上开工的 MVP 技术实施方案”。

本版做出三项关键调整：

1. **MCP First**：从第一版开始就采用 MCP 工具化架构，方便后续扩展数据源、工具、Agent 和外部能力。
2. **暂不考虑数据脱敏**：MVP 阶段不做持仓、标的、用户信息的自动脱敏与还原。
3. **暂不考虑正式鉴权**：MVP 阶段先以本地/内测使用为主，不实现完整登录、权限、Session 安全体系。

本版重点回答：

- 第一阶段到底做什么
- 架构如何切分
- MCP 怎么设计才不拖慢进度
- 8 周内如何交付一个可演示、可内测、可扩展的版本

## 1. MVP 目标

### 1.1 产品目标

MVP 只验证一条主链路：

```text
用户提问
  -> 主持人判断讨论模式
  -> 多个顾问 Agent 并行分析
  -> 顾问通过 MCP 工具获取数据
  -> 主持人综合共识、分歧、风险和关键变量
  -> 前端流式展示结果
  -> 保存会话记录
```

### 1.2 MVP 不做什么

以下能力暂不进入第一阶段：

- 正式注册、登录、会员权限、支付
- 数据脱敏、跨境隐私隔离、敏感字段自动清洗
- 微信服务号
- 复杂研报 RAG
- 调仓沙盒
- 原生 App
- 完整后台管理系统
- 大规模多租户运维

### 1.3 MVP 成功标准

| 指标 | 目标 |
|---|---|
| 能否完成一轮圆桌对话 | 是 |
| 默认顾问数量 | 3 位顾问 + 1 位主持人 |
| 全员模式 | 支持 6 位顾问，但不作为默认 |
| 首屏响应 | < 2s 显示“正在讨论”状态 |
| mini 圆桌完成时间 | p50 < 20s |
| full 圆桌完成时间 | p50 < 40s |
| 数据工具 | 至少打通 market / portfolio / news |
| 会话保存 | Postgres 持久化 |
| 前端体验 | 可连续追问、可查看顾问观点、可查看主持人总结 |

## 5. 服务划分

### 5.1 服务清单

MVP 阶段采用“模块化单体 + 独立 MCP 进程”的服务划分。业务主流程集中在 FastAPI 后端，数据工具通过 MCP server 边界隔离。

| 服务 | 技术 | 是否独立进程 | 职责 |
|---|---|---:|---|
| frontend | Next.js | 是 | 页面、交互、SSE 消费、会话展示 |
| backend-api | FastAPI | 是 | REST/SSE API、会话管理、圆桌编排入口 |
| orchestrator | Python module | 否，backend 内部模块 | Router、Conductor、Advisor 调度、总结 |
| mcp-market | MCP Python SDK | 是 | 行情、K线、财务摘要、标的搜索 |
| mcp-portfolio | MCP Python SDK | 是 | 持仓、组合摘要、单标的仓位 |
| mcp-news | MCP Python SDK | 是 | 新闻搜索、标的相关新闻 |
| mcp-research-rag | MCP Python SDK | 是，MVP 可空实现 | 研报检索 |
| mcp-calendar | MCP Python SDK | 是，MVP 可空实现 | 财报日、分红日、宏观日历 |
| worker | Celery | 是 | 早报、异步任务、后续定时扫描 |
| beat | Celery Beat | 是 | 定时任务触发 |
| postgres | Postgres | 是 | 业务数据持久化 |
| redis | Redis | 是 | 缓存、任务队列、短状态 |

### 5.2 前端职责

前端只负责产品体验，不承载业务判断。

职责：

- 新建会话、展示历史会话
- 提交用户问题
- 消费 `/api/chat` SSE 事件
- 渲染顾问观点卡片
- 渲染主持人总结
- 编辑 demo 持仓
- 展示工具失败、Agent 失败、请求中断等状态

前端不做：

- Agent 路由判断
- 数据源访问
- MCP 工具调用
- Prompt 拼接
- 成本统计

### 5.3 后端 API 职责

`backend-api` 是系统主入口。

职责：

- 提供 REST API
- 提供 SSE 流
- 创建和保存 conversation / message
- 调用 orchestrator
- 统一记录 token、模型、工具调用摘要
- 将 Agent 事件转换为前端事件
- 处理错误降级

核心接口：

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/chat` | POST | 发起一次提问，返回 SSE |
| `/api/conversations` | GET | 会话列表 |
| `/api/conversations/{id}` | GET | 会话详情 |
| `/api/portfolio` | GET | demo 持仓 |
| `/api/portfolio` | PUT | 更新 demo 持仓 |
| `/api/health` | GET | 健康检查 |

### 5.4 Orchestrator 职责

Orchestrator 是后端内部模块，不单独拆服务。

职责：

- 根据问题选择 `solo / mini / full`
- 选择参与顾问
- 为每个顾问构造 Agent options
- 注入 system prompt 和 Skills
- 提供 MCP server 配置
- 并发执行顾问
- 解析顾问结构化输出
- 调用主持人综合
- 产出统一事件流

不拆成独立服务的原因：

- MVP 阶段调试方便
- 避免过早引入 RPC / 队列复杂度
- Agent 编排和 API 流式返回强相关

后续如果并发增长，可以把 Orchestrator 拆成独立 `roundtable-service`。

### 5.5 MCP 服务职责

MCP server 是 Agent 能力边界。所有外部数据访问都应该走 MCP，而不是让 Agent 直接访问数据库或数据源 SDK。

原则：

- MCP server 只暴露稳定业务工具，不暴露底层数据库细节。
- MCP server 内部可以调用 Provider、Postgres、Redis、RSS。
- MCP 工具返回强 schema。
- MCP 工具失败时返回结构化错误，不让 Agent 看到 traceback。
- MCP server 不负责 Agent prompt，不做自然语言总结。

### 5.6 Worker 职责

Celery Worker 不参与实时对话主链路。

MVP 职责：

- 生成 daily brief 雏形
- 后台同步新闻
- 后台刷新缓存
- 后续可做成本统计、会话摘要、批量评测

实时圆桌不要丢给 Celery，否则 SSE 复杂度会上升。实时请求先在 FastAPI async 链路内完成。

### 5.7 服务调用关系

```text
用户浏览器
  -> frontend
  -> backend-api /api/chat
  -> orchestrator
  -> Claude Agent SDK
  -> MCP client
  -> mcp-market / mcp-portfolio / mcp-news
  -> Provider / Postgres / Redis
  -> orchestrator 汇总
  -> backend-api SSE
  -> frontend 渲染
```

### 5.8 为什么不是微服务

MVP 不采用完整微服务。原因：

- 当前主要风险是主链路能否跑顺，不是服务扩展性。
- MCP 已经提供了工具边界，足够支撑后续扩展。
- FastAPI 模块化单体更利于快速调试。
- 数据库 schema 还会快速变化，过早拆服务会拖慢迭代。

推荐边界：

```text
业务编排：模块化单体
工具能力：MCP 独立进程
异步任务：Celery 独立进程
```

## 6. MCP First 设计

### 6.1 MCP 设计原则

本项目从第一版开始 MCP 化，但采用 **MCP First，不做 MCP Full** 的策略。

含义：

- 工具边界从一开始就按 MCP 设计。
- Agent 只能通过 MCP 工具获取外部数据。
- 第一阶段只实现少量稳定工具。
- 不追求完整金融数据平台。
- 工具协议保持稳定，内部数据源可以替换。

### 6.2 MCP Server 划分

| Server | MVP 状态 | 说明 |
|---|---|---|
| market | 必做 | 行情、K线、财务摘要 |
| portfolio | 必做 | 当前持仓、历史快照、盈亏 |
| news | 必做 | 新闻搜索、标的相关新闻 |
| research_rag | 预留 | MVP 可先返回空结果或本地样例 |
| calendar | 预留 | 财报日、分红日、宏观事件 |

### 6.3 MVP 工具清单

#### market

```text
market.get_price(symbol)
market.get_kline(symbol, period, count)
market.get_fundamentals(symbol)
market.search_symbol(keyword)
```

#### portfolio

```text
portfolio.get_holdings(member_id)
portfolio.get_position(member_id, symbol)
portfolio.get_portfolio_summary(member_id)
```

#### news

```text
news.search(query, limit)
news.get_recent_by_symbol(symbol, limit)
```

#### research_rag

```text
research_rag.search_reports(query, symbol, top_k)
```

MVP 可以先返回：

```json
{
  "items": [],
  "message": "research_rag is not enabled in MVP"
}
```

#### calendar

```text
calendar.upcoming_events(symbol)
```

MVP 可以先返回空列表。

### 6.4 MCP 工具输入约定

即使 MVP 不做鉴权，也保留上下文字段，方便未来扩展。

```json
{
  "member_id": "demo-member",
  "session_id": "demo-session",
  "symbol": "600519.SH"
}
```

规则：

- `member_id` 和 `session_id` 在 MVP 可以是固定 demo 值。
- 工具可以暂不校验权限。
- 不要把上下文字段写死在工具内部。
- 后续增加鉴权、审计、脱敏时，不需要改 Agent 调用协议。

### 6.5 MCP 工具输出约定

所有工具返回结构化 JSON，必须包含：

```json
{
  "ok": true,
  "data": {},
  "source": "choice",
  "as_of": "2026-05-26T10:00:00+08:00",
  "error": null
}
```

失败时：

```json
{
  "ok": false,
  "data": null,
  "source": null,
  "as_of": "2026-05-26T10:00:00+08:00",
  "error": {
    "code": "DATA_UNAVAILABLE",
    "message": "market data is temporarily unavailable"
  }
}
```

Agent prompt 中明确要求：

- 工具返回 `ok=false` 时，不要编造数据。
- 缺数据时说明缺口。
- 所有数字必须来自工具返回。

### 6.6 MCP 并发策略

v2 不采用“所有 Agent 共用一个裸 stdio 会话”的假设。

推荐实现：

- 每个 MCP server 是独立进程。
- 后端负责启动和管理 MCP server 配置。
- 每次圆桌请求创建独立 MCP client session。
- 多个 Agent 可以并发调用同一类 server，但请求上下文隔离。
- 工具层必须设置 timeout，避免单个工具卡死整个圆桌。

默认 timeout：

| 工具类型 | timeout |
|---|---|
| 行情 | 2s |
| 财务 | 5s |
| 新闻 | 5s |
| 研报检索 | 8s |

## 7. Agent 编排

### 7.1 Agent 构成

| Agent | 角色 | MVP 默认 |
|---|---|---|
| 执棋 | 主持人、综合者 | 必选 |
| 韬叔 | 宏观 | mini 常用 |
| 岚姐 | 行业 | mini 常用 |
| 明哥 | 价值 | mini 常用 |
| 锐锋 | 趋势 | full 启用 |
| 冷川 | 风险 | full 或高风险问题启用 |
| 零度 | 量化 | full 或量化问题启用 |

### 7.2 讨论模式

| 模式 | Agent 数量 | 场景 |
|---|---|---|
| solo | 1 顾问 | 明确单一问题，如估值、技术形态 |
| mini | 3 顾问 + 主持人 | 默认模式 |
| full | 6 顾问 + 主持人 | 复杂持仓、重大决策、深度分析 |

### 7.3 默认策略

MVP 默认使用 mini：

```text
韬叔 + 岚姐 + 明哥 + 执棋
```

命中以下情况时启用 full：

- 用户明确要求“全员讨论”
- 问题涉及大额持仓决策
- 问题涉及多个资产类别
- 问题同时包含宏观、行业、个股、风险、趋势、量化

### 7.4 编排流程

```text
1. 接收用户问题
2. Router 判断模式：solo / mini / full
3. Conductor 选择顾问列表
4. 并行启动顾问 Agent
5. 每个顾问通过 MCP 工具取数
6. 每个顾问返回结构化观点
7. Conductor 综合输出
8. SSE 推送阶段事件和最终结果
9. 保存会话与消息
```

### 7.5 顾问输出协议

顾问输出不要求边生成边流式解析。MVP 采用“顾问完成后一次性返回结构化 JSON”。

```json
{
  "agent": "ming_ge",
  "stance": "bullish | neutral | bearish | conditional",
  "confidence": 0.72,
  "summary_for_user": "两三句话结论",
  "key_points": [
    {
      "claim": "核心判断",
      "detail": "依据说明",
      "source_tool": "market.get_fundamentals"
    }
  ],
  "concerns": ["主要风险"],
  "what_could_change_my_mind": ["关键变量"]
}
```

### 7.6 主持人输出协议

主持人综合可以流式输出自然语言，同时最终保存结构化结果。

```json
{
  "verdict": "strong_consensus | weak_consensus | split",
  "consensus": ["共识点"],
  "disagreements": [
    {
      "point": "分歧点",
      "sides": {
        "positive": ["支持理由"],
        "negative": ["反对理由"]
      }
    }
  ],
  "key_variables": ["关键变量"],
  "risk_map": [
    {
      "risk": "风险",
      "severity": 3,
      "mitigation": "应对方式"
    }
  ],
  "final_summary": "面向用户的总结"
}
```

## 8. Skills 体系设计

### 8.1 Skills 的定位

Skills 是 Agent 的行为约束层，用来解决三个问题：

1. **输出格式一致**：同类任务使用统一结构。
2. **分析过程稳定**：避免顾问跳步、凭空发挥。
3. **角色风格可维护**：不用把所有规则塞进 7 个 system prompt。

MVP 中 Skills 不承担数据脱敏和鉴权职责。

### 8.2 Skills 与 Prompt 的边界

| 类型 | 放在哪里 | 例子 |
|---|---|---|
| 角色人格、口吻、专长 | Agent system prompt | 明哥偏价值，锐锋偏趋势 |
| 通用输出规则 | Skill | 数字必须带来源、观点必须给置信度 |
| 特定任务格式 | Skill | DCF、财报点评、行业分析 |
| 方法论步骤 | Skill | 风险评估、可比公司分析 |
| 工具使用约束 | Skill | 估值必须先取财务数据 |

原则：

- system prompt 保持短而稳定。
- Skill 负责可复用规则。

### 8.6 SkillRegistry 设计

```python
from pathlib import Path
from typing import Iterable

SKILLS_ROOT = Path(__file__).parent

class SkillRegistry:
    ALWAYS_ON = [
        "common/evidence_citation",
        "common/structured_opinion",
        "common/no_fabrication",
    ]

    TRIGGER_BASED = {
        "output_templates/dcf_valuation": ["DCF", "估值", "内在价值", "公允价值", "自由现金流"],
        "output_templates/earnings_review": ["财报", "季报", "年报", "业绩"],
        "output_templates/industry_landscape": ["行业", "赛道", "竞争格局", "产业链"],
        "output_templates/comparable_analysis": ["可比公司", "估值倍数", "对标"],
        "methodology/risk_assessment": ["风险", "压力测试", "下行", "黑天鹅"],
        "methodology/scenario_analysis": ["情景", "乐观", "中性", "悲观"],
    }

    AGENT_BOUND = {
        "ming_ge": ["agent_bound/value_methodology"],
        "rui_feng": ["agent_bound/trend_methodology"],
        "ling_du": ["agent_bound/quant_backtesting"],
    }

    def resolve(
        self,
        *,
        question: str,
        agent: str,
        task_context: str = "",
        force_skills: list[str] | None = None,
    ) -> list[str]:
        skills = list(self.ALWAYS_ON)
        haystack = (question + " " + task_context).lower()

        for skill_path, keywords in self.TRIGGER_BASED.items():
            if any(keyword.lower() in haystack for keyword in keywords):
                skills.append(skill_path)

        skills.extend(self.AGENT_BOUND.get(agent, []))

        if force_skills:
            skills.extend(force_skills)

        return list(dict.fromkeys(skills))

    def load_texts(self, skill_paths: Iterable[str]) -> list[str]:
        texts = []
        for skill_path in skill_paths:
            path = SKILLS_ROOT / skill_path / "SKILL.md"
            texts.append(path.read_text(encoding="utf-8"))
        return texts
```

```text

  -> 查 Redis 缓存
  -> Choice
```

### 10.3 缓存策略

| 数据 | 缓存 |
|---|---|

## 17. 最终结论

在暂不考虑数据脱敏和正式鉴权的前提下，圆桌投研 MVP 可以实现。

v2 推荐采用：

```text
MCP First
Mini Roundtable First
Main Flow First
```

也就是：

- 从第一天开始 MCP 化，保证后续扩展性。
- 第一版默认 3 顾问，不把 7 Agent 全员讨论作为常规路径。
- 优先打穿“提问 - 工具 - 分析 - 综合 - 展示 - 保存”的主链路。

这样既不会牺牲长期架构，也不会让第一阶段陷入过度平台化。
